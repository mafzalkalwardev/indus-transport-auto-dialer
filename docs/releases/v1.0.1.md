# v1.0.1 — Dial Reliability & CRM Sustained QA

**Indus Transports Auto Dialer** — production-ready dial path, CRM-only sustained testing, client delivery docs.

## Highlights

### Dial reliability
- Voicemail hangup no longer stalls slots (smoke runner owns hangup; GV internal hangup deferred in headless tests)
- Dial field cleared between calls; Enter-key fallback after Call click
- Extended retry path when Call click does not open panel (`retry_start_call`, alternate GV URL)
- Fixed async JS race when clearing the dial input

### CRM sustained testing (`scripts/deep_live_test.py`)
- Loads **fresh CRM numbers only** — excludes all numbers from prior live/deep/campaign reports
- Never redials the same number in one session; refills from CRM until time target met
- **Recommended:** `--min-minutes 7 --max-parallel 3` (sequential, one call at a time)
- Profile cloning for extra slots (Johnson + Barry)
- JSON report + summary under `logs/`

### Multi-line stability
- Sequential gate waits for **full call completion** before next line dials
- Staggered WebEngine boot (2s per slot)
- Concurrent parallel dial disabled by default (`--force-parallel-dial` for experiments only)

### Client delivery
- [docs/QA_VERIFICATION.md](../QA_VERIFICATION.md) — administrator pre-handoff checklist
- [Run CRM Sustained Test.bat](../../Run%20CRM%20Sustained%20Test.bat) — one-click QA on admin PC
- Updated [CLIENT_DELIVERY.md](../../CLIENT_DELIVERY.md) and [RUNBOOK.md](../RUNBOOK.md)

## Upgrade from v1.0.0

1. Pull/copy updated source or rebuild EXE with `Build Auto Dialer.bat`
2. Existing `dialer_config.json` and CRM database are compatible
3. Re-sign-in any GV line that shows login required in Settings
4. Run [QA_VERIFICATION.md](../QA_VERIFICATION.md) before client export
